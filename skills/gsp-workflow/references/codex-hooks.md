# Codex hook contract

Codex-first native hooks are installed separately with explicit user authorization: `<gsp> hooks-install` (global current user); hooks-status; hooks-upgrade; hooks-uninstall; hooks-recover. Maintenance supports --profile and --dry-run. Preserve notifier and unrelated groups, refuse edited owned files or registrations, never change trust hashes. User reviews new/changed hooks through native /hooks; a fresh session must prove actual activation.

Only GSP projects receive context/checks/audit. SessionStart reminds active task and bindings; PreToolUse checks supported direct edit paths against existing scope; direct-edit target paths resolve the source worktree before choosing the task state; PostToolUse records arrival; Stop/Interrupt/SessionEnd record observations without resuming work, approving design, clearing locks or mutating progress. Arbitrary shell and specialized/hosted tool side effects remain outside full enforcement. No sandbox claim.

For a `PreToolUse` empty wait, including a `write_stdin` or a `Bash`/`exec_command` alias with wait-shaped input, wait-guard tracks the hashed outer session and tool session. String and integer tool session ids are equivalent. The first two waits are allowed. The third wait is denied until another observation or input occurs. Changing `yield_time_ms` or `max_output_tokens` does not reset the budget. A real shell command does not count as a wait. State is bounded, locked and metadata-only. A storage failure reports degraded coverage and allows the call. Denials are recorded as `coverage=wait-guard`; native host trust and event delivery remain `NOT_CHECKED`.

**Live delivery limit (2026-11-24):** the current Codex host does not emit another `PreToolUse` for `write_stdin` polls of an existing exec session; a probe of three empty waits produced zero hook events and `wait_guard_denied=0`. Therefore wait-guard cannot enforce the poll budget on this host even though alias code and fixtures exist. The active prevention is the execution rule: at most two empty waits, then read the log, process, exit code or artifact. Wait-guard remains forward-compatible for hosts that do deliver wait-shaped alias events. Do not claim live enforcement until a native denial is observed.

Metadata audit: `.gsp/audits/codex-hooks/<hashed-session>/events-*.jsonl` and coverage.json. No raw prompts, commands, tool results or environment. Bounded storage and independent OS lock; unavailable audit reports degraded coverage. `<gsp> hooks-report` returns bounded offline counts including unknown attempts and duplicate events; no result is not proof of failure, no event is not proof an operation did not happen. File integrity/status is not live trigger evidence. Do not stack Claude-specific hooks or silently enable global hooks during ordinary skill installation.

Codex user skill install/upgrade returns hooks status and maintenance comparison against the executing source package. Inspect source_version, changed_files, removed_files, registrations_changed and next_command. Distinguish current, version-label-update, runtime-update, registration-update, not-installed, source-unavailable and repair-required. A pending transaction takes priority as recovery-required with hooks-recover, while retaining available source differences. Never silently upgrade hooks as part of a skill install; use existing precise maintenance authorization, backups and native trust verification.
