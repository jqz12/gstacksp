# 用户级安装维护

## 先选择安装范围

安装前先提示并确认范围；已明确选择则不重复问。

| 方式 | 命令参数 | 技能存放位置 | 适用范围 |
|---|---|---|---|
| 项目级 | --scope project | 目标项目的 .agents/skills/gsp-*（Codex）或 .claude/skills/gsp-*（Claude） | 该项目单独配置 |
| 用户全局级 | --scope user | 当前用户宿主 profile 下的 skills/gsp-* | 当前用户多个项目共用 |

用户全局安装不会在新目标项目中复制 .agents/skills/gsp-*，也不会自动删除已有项目级安装；.agents 还可能存有其他工具文件。全局指当前用户，不是系统所有账户。无论选哪种，规格、计划、待办、状态和证据仍属于各自目标项目。

```powershell
# Codex 用户全局安装：当前用户多个项目共用
python E:/GstackSP/scripts/gsp.py install --scope user --host codex
# 项目安装：只复制到指定项目（安装命令省略 scope 时仍默认 project）
python E:/GstackSP/scripts/gsp.py --project E:/MyProject install --scope project --host codex
```

CLI 安装前向 stderr 显示两级解释、当前选择和实际路径，stdout 保持 JSON 接口；直接脚本调用不弹交互菜单。由 AI 协助安装且未指定范围时，AI 先询问一次选择。


项目安装仍使用原来的 `install --host ...`。用户级安装必须选定宿主；Codex 默认目录为 `%USERPROFILE%\.codex`，Claude 为 `%USERPROFILE%\.claude`，两者分别维护。`--profile` 可显式指定独立目录，适合测试或自定义宿主配置。不会安装父本、启用 Claude hooks、修改 settings.json 或连接 gbrain。

## 常用命令

从源码目录或解压后的源码包运行；升级不能使用已安装技能内的运行时作为来源，因为它不包含完整发布源。卸载、事务恢复可使用仍可运行的安装内 CLI，建议始终保留源包。

```powershell
python E:\GstackSP\scripts\gsp.py install --scope user --host codex --dry-run
python E:\GstackSP\scripts\gsp.py install --scope user --host codex
python E:\GstackSP\scripts\gsp.py upgrade --scope user --host codex --dry-run
python E:\GstackSP\scripts\gsp.py upgrade --scope user --host codex
# 开发者离线维护才显式使用本地 checkout，不参与普通用户更新流程
python E:\GstackSP\scripts\gsp.py upgrade --scope user --host codex --source local
python E:\GstackSP\scripts\gsp.py uninstall --scope user --host codex --dry-run
python E:\GstackSP\scripts\gsp.py uninstall --scope user --host codex
```

核心默认安装；额外技能沿用 `--optional`。升级保留之前选择的可选技能，并可追加选项。需要更换可选集合时先卸载再重新安装。`--host both` 不支持用户级操作，分别指定每个宿主，避免跨宿主误操作。项目级升级继续使用原项目级 install；本页新增的维护命令只适用于用户级。

## 文件归属与操作保护

只维护 `skills/gsp-*` 内归属清单列出的文件，和 AGENTS.md/CLAUDE.md 内相应 `gstacksp:<宿主>-user` 引导块。其它技能、引导块之外的个人内容、宿主配置保持不变。预检发现未知文件、受管文件被编辑/丢失、引导块被编辑、路径逃逸或链接时，整次操作拒绝，不自动覆盖或删除。

原手工 Codex 安装清单首次升级会核对已登记的整个引导文件哈希，之后使用引导块哈希，允许独立修改块外的个人内容。卸载只删除列明且哈希匹配的文件，去掉受管引导块，保留目录、备份及无关内容；不会清理用户的项目记录。

## 备份与恢复

profile 下 `gstacksp/install.json` 是安装归属清单；`gstacksp/backups/<事务ID>/` 保存变更前的文件及 operation.json。备份数字文件名通过 operation.json 映射原路径。备份不随卸载删除，用户可另行归档。新建文件的历史为空，回滚只撤销该次新建内容。

`gstacksp/transaction.json` 存在表示操作中断，新的维护操作会拒绝。运行：

```powershell
python E:\GstackSP\scripts\gsp.py install-recover --scope user --host codex --dry-run
python E:\GstackSP\scripts\gsp.py install-recover --scope user --host codex
```

恢复只回滚未完成事务，不猜测完成。会先确认全部当前文件属于已知操作前/后状态，备份完好，且相关锁持有者已退出；有人改过则保留现场并拒绝。仅清理由事务 PID 和创建身份共同确认已经结束的精确安装锁，不按等待时间抢锁。若中断发生在事务建立前、没有事务可核对，则仍需人工调查锁，不自动删除。

安装更新完成后需重新加载宿主技能；文件完整性检查不代表真实模型已经遵循流程。

## 通过健康检查发现并确认升级

健康检查是用户级更新的统一入口。它只读检查当前受管安装，并按宿主 profile 在
`gstacksp/update-check.json` 保存 24 小时缓存；检查会访问 GitHub 稳定 `vX.Y.Z` 标签，
但不会因为发现更新而修改技能文件：

```powershell
python E:\GstackSP\scripts\gsp.py --project E:\MyProject health --host claude
# 需要立刻绕过 24 小时缓存时
python E:\GstackSP\scripts\gsp.py --project E:\MyProject health --host claude --force-update-check
```

输出中的 `<host>-user-update` 行含义如下：

| 状态 | 含义 | 下一步 |
|---|---|---|
| `UPDATE_AVAILABLE` | GitHub 有高于当前 `source_version` 的稳定 tag | 把 current/latest/source 展示给用户，获得明确确认后再升级 |
| `PASS` | 当前已是最新稳定 tag，或远端没有更高版本 | 继续当前工作 |
| `NOT_CHECKED` | 网络、GitHub 或本地清单不可用 | 保留当前安装，稍后重试；不当作已是最新 |

确认升级后，使用对应宿主的用户级命令；默认升级会重新解析 GitHub 稳定 tag，完成暂存、
完整性检查、备份和原子写入，并把 `source_version`、`source_commit` 和远端来源写入
`gstacksp/install.json`：

```powershell
python E:\GstackSP\scripts\gsp.py upgrade --scope user --host claude
```

`--source local` 是开发者明确选择的离线维护入口。普通用户升级和 `--dry-run` 默认都解析
GitHub 稳定 tag，不能通过当前 checkout 或已安装技能目录静默替代发布源。

升级失败保留原安装并给出恢复入口。升级完成后重新启动 Claude/Codex 会话，再运行一次
`health` 复查；静态文件完整性仍不等于真实宿主已经加载新技能。
