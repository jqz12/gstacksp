# 实际发布技能目录

6 个默认入口默认安装，4 个维护入口按需点名安装。28 项内部来源职责由 26 个独立 `METHOD.md` 和 1 份共享的 workflow 业务恢复说明承载；12 个旧包装完全退役。唯一清单为 `skills/skill-manifest.json`，生成源、校验、打包和安装均由 `gsp/skill_catalog.py` 读取，`scripts/build_skills.py` 只负责生成投影。

## 公开入口

| 技能 | 类别 | 触发 |
|---|---|---|
| `gsp-workflow` | 默认 | 开始或恢复业务项，需要选择当前阶段和方法 |
| `gsp-brainstorming` | 默认 | 目标、范围或方案仍需确认 |
| `gsp-writing-plans` | 默认 | 已确认设计需要拆成可验收切片 |
| `gsp-execute` | 默认 | 按 TaskContract、TDD 和资源边界实施 |
| `gsp-review` | 默认 | 需要独立规格/质量审查与最终整体审查 |
| `gsp-ship` | 默认 | 准备提交、合并、资源收敛和交付 |
| `gsp-health` | 按需 | 检查安装、文档、Git 和宿主事实 |
| `gsp-document-governance` | 按需 | 新项目接入或老项目文档治理 |
| `gsp-writing-skills` | 按需 | 新增或修改可复用 GSP 技能 |
| `gsp-diagnosing-superpowers` | 按需 | 只读诊断指定会话的重复工作和成本 |

## 条件内部方法

28 项内部来源职责不会作为独立技能被宿主发现。入口只在实际触发条件成立时读取 [方法索引](../skills/gsp-workflow/references/methods.md) 中的完整方法；当前上下文和方法版本未变化时不重复读取。TDD、系统调试、code quality、verify、review 附件和完整 Superpowers 父本正文继续保留。

plan-tune 的设计咨询、设计评审、开发者体验、浏览器/QA、Git 交付、资源恢复等职责由阶段入口在对应条件下加载；它们不要求每个任务执行全部清单。`context-save` 与 `context-restore` 两个来源保留独立 provenance 和 digest，但共享同一份 workflow 业务恢复说明，不生成两个重复的公开入口或物理方法。

## Codex 原生运行事实

Codex 原生聊天、代理、历史、压缩/恢复、模型参数和 worktree 负责运行生命周期；GSP 保存业务编号、TaskContract、主体代际、租约和必要证据。Goal 仅在用户明确创建目标时使用。`drive-*` 只作为 legacy 兼容入口，不进入默认路由。

## Git 拓扑与身份

每个新任务第一次实现前，由 `gsp-ship` 的 Git 条件方法运行 `topology`，盘点当前分支、HEAD、全部 worktree、脏状态和任务绑定；再用 `topology-select` 记录原地、分支或 worktree。`main/master`、detached HEAD、共享可写 worktree 和重复分支默认阻塞。

身份分层固定为：GSP 编号、T 任务号、branch、commit SHA、control_root、workspace_root、Issue/PR 和 Codex 原生会话/代理 ID。commit SHA 只在真实提交后记录，Issue/PR 仅关联真实对象；中文标题和分支主题可用，稳定类型前缀保持 ASCII。
