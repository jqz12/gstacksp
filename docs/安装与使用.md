# 安装与使用

GstackSP 当前只服务 Codex。发布面只有 6 个默认入口和 4 个按需入口；28 项内部来源职责以 26 个条件 `METHOD.md` 加 1 份共享业务恢复说明保留，不进入默认技能列表。

## 公开入口

默认入口：`gsp-workflow`、`gsp-brainstorming`、`gsp-writing-plans`、`gsp-execute`、`gsp-review`、`gsp-ship`。

按需入口：`gsp-health`、`gsp-document-governance`、`gsp-writing-skills`、`gsp-diagnosing-superpowers`。

`gsp-health` 在安装、依赖或文档需要检查时使用；`gsp-document-governance` 处理新项目接入或老项目整理；`gsp-writing-skills` 只在新增/修改 GSP 技能时使用；`gsp-diagnosing-superpowers` 只在用户指定会话并要求诊断时使用。它们不进入每个任务的默认路径。

## 安装范围

安装前确认项目级或用户级范围，并展示实际目标路径；已有明确选择直接沿用。

| 范围 | 参数 | 位置 |
|---|---|---|
| 项目级 | `--scope project` | 目标项目 `.agents/skills/gsp-*` |
| 用户级 | `--scope user` | 当前 Codex profile 的 `skills/gsp-*` |

项目安装示例：

```powershell
python E:\GstackSP\scripts\gsp.py --project E:\MyProject install --host codex
python E:\GstackSP\scripts\gsp.py --project E:\MyProject init
python E:\GstackSP\scripts\gsp.py --project E:\MyProject health --host codex
```

用户级安装示例：

```powershell
python E:\GstackSP\scripts\gsp.py install --scope user --host codex
```

按需入口通过明确点名安装，例如：

```powershell
python E:\GstackSP\scripts\gsp.py --project E:\MyProject install --host codex --optional writing-skills
```

安装、升级和退役都消费 `skills/skill-manifest.json`。旧 `files` 与当前 `skills` 的并集不会重新带回退役入口；自有文件按哈希清理，用户修改或未知文件保留并报告冲突。实际全局安装、升级和卸载必须在用户明确授权后执行。

安装后重新加载 Codex 技能列表并实际调用 `$gsp-workflow`。静态文件检查、CLI 存在和真实技能触发是不同证据。

## 默认阶段

1. `gsp-brainstorming`：阅读现有资料，确认目标、非目标、方案和验收。
2. `gsp-writing-plans`：把设计拆成独立可验收切片，写明文件、Writes、测试、资源与恢复。
3. `gsp-execute`：按一份完整 TaskContract 和 TDD/SDD 实施；方法按条件加载。
4. `gsp-review`：独立规格与质量审查，修复发现后重新验证。
5. `gsp-ship`：最终 all 回归、整体审查/verify、提交、合并、推送授权、资源处置和交付。

常规推进用一次 `advance` 完成当前可判定预检、版本复核和阶段转换；`handoff` 只用于需要主动预览下一阶段或责任转移。用户明确创建 Goal 时才使用 Goal；Codex 原生聊天、代理、历史和 worktree 是运行事实源。

## 命令示例

下面的 `--quote` 必须取自真实用户指示，不能照抄示例当授权。

```powershell
python E:\GstackSP\scripts\gsp.py --project E:\MyProject new login --title "登录功能"
python E:\GstackSP\scripts\gsp.py --project E:\MyProject approve login --quote "实际确认原话"
python E:\GstackSP\scripts\gsp.py --project E:\MyProject task-add login T1 --title "实现登录" --acceptance "正确密码成功，错误密码拒绝"
python E:\GstackSP\scripts\gsp.py --project E:\MyProject seal-plan login
python E:\GstackSP\scripts\gsp.py --project E:\MyProject advance login --to execute
python E:\GstackSP\scripts\gsp.py --project E:\MyProject task-start login T1
python E:\GstackSP\scripts\gsp.py --project E:\MyProject run login --task T1 --kind tests -- python -m unittest discover -s tests -v
python E:\GstackSP\scripts\gsp.py --project E:\MyProject task-done login T1
python E:\GstackSP\scripts\gsp.py --project E:\MyProject run login --task all --kind tests -- python -m unittest discover -s tests -v
```

`run` 不执行隐式字符串 shell；`--` 后是独立 argv。真正需要 PowerShell 时显式指定 `powershell -NoProfile -Command ...`，并承担该命令实际副作用。

## Git 拓扑与资源

首次实现前运行 `topology`，再以真实用户原话执行 `topology-select`。每个 GSP 编号、T 任务号、branch、commit SHA、control_root、workspace_root、Issue/PR 和 Codex 原生会话/代理 ID 分属不同身份层，不能互相替代。

小改和串行工作可沿用当前位置；并行写者、独立验证或保护现有改动时使用 Codex 原生 worktree。创建前登记资源 owner、路径、用途和清理策略。managed worktree、bound worktree、构建根和缓存按真实所有权分别处置：managed 由 owner 收敛，bound 只释放租约，缺失路径不等于已完成物理删除。

## 质量与证据

每个任务先登记真实 Red/Green，再运行项目声明的 build、lint、测试和其他 required checks。最终候选运行 all 回归、独立规格与质量审查、整体审查和 verify。相同输入、argv、工作区、环境、工具、模型、契约、阶段和覆盖均可证明等价时复用已有结果；未知终态、日志截断、后续失败或输入漂移继续阻断。

质量报告绑定实际 source inputs、配置、环境和工具摘要。纯状态查询零写入、零 Git 和零全仓扫描；普通状态变更不同步重建看板或普通汇总。性能验收同时记录实际进程、Git/扫描/写入、模型往返、全树 Token 和端到端墙钟。

## 恢复与交付

持久副作用之前先写 intent；未知结果按原 request 查询真实文件、进程和 worktree 状态，不盲重发。Codex 原生历史/压缩负责会话延续，GSP `save/resume` 只恢复经核验的业务绑定和证据。缺失 worktree 时从控制根和资源登记恢复，不依赖已删除目录重建判断。

`gsp-ship` 的顺序是：验收候选、提交、基于最新目标构造并验证合并候选、目标版本/检出分支租约复核、落地、按授权推送、处置本任务资源、最后关闭业务项。任何资源清理失败都保持逐资源 pending；未解决必需问题继续阻断交付。

## 完整 SP 与退役

完整 Superpowers 正文及其附件保留在条件方法或上游镜像中，不以摘要替换。12 个旧包装完全退役，不通过改名、默认安装或打包重新出现。既有用户经验数据、Codex 历史、worktree 和 gbrain 配置不会因技能退役自动删除。
