# 安装与使用

Codex 原生全局 hooks 现通过独立命令安装和维护，见 [Codex 全局 hooks](Codex全局hooks.md)。下文旧版空 hooks 描述指插件清单及技能安装不会自动注册 hooks，不表示 Codex 无此能力。

## 先选择安装范围

安装前先提示并确认范围；已明确选择则不重复问。

| 方式 | 命令参数 | 技能存放位置 | 适用范围 |
|---|---|---|---|
| 项目级 | --scope project | 目标项目的 .agents/skills/gsp-*（Codex）或 .claude/skills/gsp-*（Claude） | 该项目单独配置 |
| 用户全局级 | --scope user | 当前用户宿主 profile 下的 skills/gsp-* | 当前用户多个项目共用 |

用户全局安装不会在新目标项目中复制 .agents/skills/gsp-*，也不会自动删除已有项目级安装；.agents 还可能存有其他工具文件。全局指当前用户，不是系统所有账户。无论选哪种，规格、计划、待办、状态和证据仍属于各自目标项目。

```powershell
# Codex 用户全局安装：当前用户多个项目共用
python E:/GstackSP/scripts/gsp.py install --scope user --host codex
# 项目安装：只复制到指定项目（安装命令省略 scope 时仍默认 project）
python E:/GstackSP/scripts/gsp.py --project E:/MyProject install --scope project --host codex
```

CLI 安装前向 stderr 显示两级解释、当前选择和实际路径，stdout 保持 JSON 接口；直接脚本调用不弹交互菜单。由 AI 协助安装且未指定范围时，AI 先询问一次选择。


## 项目级安装

目标项目先创建目录。Python 3.10+ 可运行，无第三方 Python 运行依赖。

```powershell
python E:\GstackSP\scripts\gsp.py --project E:\MyProject install --host both
python E:\GstackSP\scripts\gsp.py --project E:\MyProject init
```

`--host claude` 只写 `.claude/skills` 和项目 CLAUDE.md；`--host codex` 只写 `.agents/skills` 和项目 AGENTS.md。both 两者都写。已有引导正文保留，管理块仅在自己标记内部更新。已有技能未知或被用户修改则报 INSTALL_CONFLICT，不静默覆盖。不会安装到用户全局目录。

可选扩展只安装点名项目，例如：

```powershell
python E:\GstackSP\scripts\gsp.py --project E:\MyProject install --host both --optional design-consultation design-review diagram
```

可重复安装未改动的自有文件升级；未再次点名的已安装可选技能保持原样。删除或迁移不提供自动强制清理，先查看 `.gsp/install-<host>.json`。

安装后重新加载宿主技能列表；若未发现，按项目引导直接读取技能文件排查。Claude 调用名称通常为 `/gsp-...`，Codex 为 `$gsp-...`；项目级安装和真实会话触发仍需当前宿主实际验证。

本机另有授权安装的 Codex 用户级实例，位于 `C:\Users\asus\.codex\skills\gsp-*`，清单在 `.codex/gstacksp/install.json`；上面的 install CLI 仍仅安装到目标项目。health 0.2.0 会分别检测项目与用户级，尊重 CODEX_HOME；任一已存在且受管理的安装损坏都会报告失败，不用另一个正常安装遮盖它。用户级升级、卸载和中断恢复入口已实现；具体命令见《用户级安装维护》。真实宿主触发仍需单独核实。

用户级更新统一从健康检查开始：`health` 会查询 GitHub 稳定 tag 并按 profile 缓存 24 小时。`UPDATE_AVAILABLE` 只报告当前版本、最新 tag、来源和缓存状态；得到用户明确确认后，才运行对应宿主的 `upgrade --scope user --host ...`，升级完成后重启宿主并再次 health 复查。需要立即重查时加 `--force-update-check`；网络失败为 `NOT_CHECKED`，不阻塞当前工作。

## 新任务的 Git 拓扑选择

新任务第一次写实现前，GSP 会先盘点当前分支、HEAD、全部 worktree、脏状态和活动任务绑定，并给出原地、分支或 worktree 推荐。只读盘点不改变 Git；选择用一次真实用户原话记录：

```powershell
python E:\\GstackSP\\scripts\\gsp.py --project E:\\MyProject topology <id>
python E:\\GstackSP\\scripts\\gsp.py --project E:\\MyProject topology-select <id> --mode branch --quote "用户选择独立任务分支"
```

默认不允许在 `main`、`master` 或 detached HEAD 上直接实现；用户明确选择原地时才记录覆盖。工作区模式使用一个 control_root 保存 `.gsp`、任务文档和证据，使用绑定的 workspace_root 执行源码命令和 fingerprint。多会话、多 agent 或全栈任务用 `task-add --role frontend|backend|integration`，再用 `topology-select <id> --task Tnn` 给每个可写任务分配独立 branch/worktree；共享写目录、重复分支、子任务未完成或缺少 integration owner 时不能 ready。

身份必须分别记录：GSP 编号是工作项，T 号是计划任务，branch 是开发路线，commit SHA 只来自真实提交，Issue/PR 只在真实对象存在时登记。中文标题和分支主题可保留，稳定类型前缀仍使用 `feature/`、`fix/`、`docs/` 等。真实远端创建、推送、合并和宿主触发不由本地拓扑选择自动执行。

## 长期待办

`init` 为新项目创建根 `TODOS.md`，已有 TODO.md 则沿用并保留内容。设计/计划/审查/QA 发现的接受延期需有来源与理由；本次必需问题仍是阻塞。`todo-list` 查询，`todo-add` 登记，`todo-done` 用已完成任务的有效证据关闭，`todo-reopen` 保留历史重新打开。完整参数与生命周期见 [共同待办规则](../skills/gsp-workflow/references/backlog.md)。先核对待办再做最终 all 回归，避免文档更新导致旧证据过期。

0.4 起 TODO 正文以人阅读为主，执行归因、关联和证据放在 `.gsp/backlog/records.json`。旧文件用 `todo-migrate` 备份迁移；`todo-format` 按现有组件/优先级整理；`todo-link` 关联任务。AI 仍读最新正文，不另维护一份问题清单。示例与迁移说明见项目根 `TODOS.md` 和目标项目本地任务记录。

## 冻结 hook 与实际覆盖

项目级技能目录安装不会改宿主 hooks 配置。源码包提供 `.claude-plugin/plugin.json` 与 `hooks/hooks.json`，Claude 以插件方式加载本源码目录后才会注册 SessionStart 和 Edit/Write/NotebookEdit PreToolUse hook。若当前 Claude 版本支持，可使用其插件目录启动方式载入本项目，并在实际会话检查 hook 日志；首版提供本地 payload 测试，不宣称完成真实宿主集成。

源码插件模式会暴露 skills/ 下全部 50 个技能，扩展仍按场景使用；希望项目只发现 22 个核心入口时，使用项目级安装，再点名需要的扩展。

Codex 插件清单显式 `hooks: {}`，避免误用 Claude hook。Codex 依赖技能在编辑前运行 `check-path` 并遵守冻结范围。PowerShell/Bash/apply_patch 不受上述 hook 自动拦截，CLI `run` 的越界检测为事后检测。需要系统级安全隔离时使用宿主或操作系统真实沙箱，不能把冻结宣传成沙箱。

## 一次任务的命令示例

这些是 AI 的工具调用，人通常只需讨论、确认设计和查看交付。以下 `--quote` 必须取自真实用户指示，不能照抄示例当授权。

```powershell
python E:\GstackSP\scripts\gsp.py --project E:\MyProject new login --title "登录功能"
# new 返回 document_paths；AI 填写 docs/work/2026/11/GSP-000001-login-design/spec.md，用户实际确认后：
python E:\GstackSP\scripts\gsp.py --project E:\MyProject approve login --quote "实际确认原话"
# AI 写计划并登记完整任务：
python E:\GstackSP\scripts\gsp.py --project E:\MyProject task-add login T1 --title "实现登录" --acceptance "正确密码成功，错误密码拒绝"
python E:\GstackSP\scripts\gsp.py --project E:\MyProject seal-plan login
# 用户未指定则先问一次；选择原地冻结且 src 已存在：
python E:\GstackSP\scripts\gsp.py --project E:\MyProject scope login --path src --quote "实际选择或既有无人值守授权和推荐依据"
python E:\GstackSP\scripts\gsp.py --project E:\MyProject advance login --to execute
python E:\GstackSP\scripts\gsp.py --project E:\MyProject task-start login T1
# AI 实现、测试；采用项目实际命令，这里只是 Python 项目示例：
python E:\GstackSP\scripts\gsp.py --project E:\MyProject run login --task T1 --kind tests -- python -m unittest discover -s tests -v
python E:\GstackSP\scripts\gsp.py --project E:\MyProject task-done login T1
# 多任务完成后最终完整回归：
python E:\GstackSP\scripts\gsp.py --project E:\MyProject run login --task all --kind tests -- python -m unittest discover -s tests -v
# 写真实 review.md 后登记结论，自查不能填写 independent：
python E:\GstackSP\scripts\gsp.py --project E:\MyProject advance login --to review
python E:\GstackSP\scripts\gsp.py --project E:\MyProject review login --reviewer self --blocking 0
python E:\GstackSP\scripts\gsp.py --project E:\MyProject advance login --to checking
python E:\GstackSP\scripts\gsp.py --project E:\MyProject advance login --to ready
python E:\GstackSP\scripts\gsp.py --project E:\MyProject ready login
python E:\GstackSP\scripts\gsp.py --project E:\MyProject save login
```

`run` 不执行字符串拼接的隐式 shell；`--` 后是可执行文件和独立参数。确实需要 PowerShell 命令时显式指定 `powershell -NoProfile -Command ...`，同时承担该命令实际副作用。单独查看每条 `--help` 获得参数。

Git 项目进入 execute 前还需完成 `topology` 和 `topology-select`。分支/worktree 选择矩阵、`--base`、`--rebind`、子任务提交观察、集成门禁及 headless 限制见[分支、worktree 与并行任务](reference/git-topology.md)。

Windows 的 npm 等工具可能是 `.cmd` 包装器，应先核对实际可执行入口；必要时显式使用 PowerShell 执行项目声明的命令。脚本不会在启动失败时偷偷改成另一个 shell，也不会把命令未启动记为测试失败或成功。

## 无人值守与外部操作

用户明确开启后，创建任务可用 `new ... --mode unattended --quote "用户原话"`。单独这个标志记录会话内连续执行授权；需要离开会话后继续时，按 [无人值守驱动器](无人值守驱动器.md) 配置真实检查并显式 drive-init/drive-start。0.3 提供 Codex headless 适配；Claude 暂仍由活跃会话执行，不能把安装技能当作后台启动。

设计仍先由用户确认。AI 将普通技术选择写 decisions.md 后继续；超出授权、可靠完成目标已不可能或达到修复上限时 block 并保存下一步。

授权推送示例：`authorize login push --scope feature/login --quote "真实原话"`；执行前 `authority login push --scope feature/login` 核对。CLI 不自行推送/合并/发布；实际由当前 AI 使用宿主工具完成并验证。没有相应授权不执行，多项授权不可相互代替。

## 纯文档任务与测试数

确无适用自动测试时，登记任务写具体 `--no-tests-reason` 并用 `--kind check` 跑真实替代检查。测试输出识别常见 unittest、pytest、Bun、Node 摘要；未识别时返回 test-count-unknown，不把未知算通过。不要为了过关把输出改成假测试摘要。检查证明命令实际执行，不自动理解需求或评估测试质量。

## 审查后返工

已完成任务需要修正时，使用 `task-reopen <id> T1 --reason "问题、依据和修正范围"`，再 task-start、实施、检查、task-done。系统保留旧完成记录，将受影响的下游任务标为 needs-verification；下游可以验证已有代码，无需重新实现。所有相关任务完成后重新跑 all 回归、登记整体审查并 ready，旧的交付不会直接沿用。

## 恢复与锁

用户级工具安装、升级、卸载及中断回滚见[用户级安装维护](用户级安装维护.md)。目标项目的有效经验、纠错与历史见[经验管理](经验管理.md)。它们不要求连接 gbrain。

`save <id>` 绑定当前项目/工作区/文档/文件；`resume <id>` 不一致时拒绝盲续。先看实际 diff 和 Git 状态，再明确重新验证，别直接改状态骗过检查。

正常任务提交改变 HEAD 后，核对提交内容再 `observe-head <id> --reason "提交号、变更范围与核对依据"`；普通 decision/authorize 不会静默更新恢复基线。分支或项目改变仍拒绝。

旧任务未冻结时，切换分支可以直接 new 新任务；旧任务恢复仍核对原分支。若旧任务还冻结，先明确 `scope <旧任务> --off --quote "解除依据"`；这可在切换分支后执行，只释放边界，不改变旧任务的 Git 基线。

若命令中途被强制终止，state 中的 inflight 表示执行结果未知。确认进程已结束、调查输出并写本地恢复报告后，`recover-run <id> --evidence <报告路径> --outcome not-run|failed` 才清除未知标记；该接口不能把未知命令登记为通过。

异常退出可能留下 `.gsp/writer.lock`。先确认其中 pid 的持有者已结束，并查看状态与最后证据；只在明确没有活跃写者时手动移除这个具体锁。系统不会因“超过几十秒”自动偷锁。命令超时仅保证当前子进程被 Python 管理，复杂子进程树/项目外写入不提供沙箱保证。

## 完整 SP 与文档分类

0.6 起保留完整 SP 正文与配套资源，不使用摘要版替代。新任务规格与计划默认在 docs/work/YYYY/MM/<固定档案>/，状态保存明确路径，旧任务兼容旧位置。详见 [项目文档索引](README.md)；研究与历史档案保存在开发工作区。
