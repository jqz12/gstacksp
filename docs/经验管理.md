# 经验去重、纠错与失效

经验回答“哪些结论已经验证”，TODO 回答“还有什么没解决”。两者分开保存。AI 使用经验前先核对适用条件、来源和当前状态，不能把经验当作授权。

## 保存和查询

```powershell
python scripts/gsp.py --project E:\MyProject learn --text "结论及适用条件" --source "任务或证据位置"
python scripts/gsp.py --project E:\MyProject learn --query "关键词"
python scripts/gsp.py --project E:\MyProject learn --query "关键词" --history
```

查询默认只返回 active 条目。相同结论按 Unicode 规范化、空白折叠和大小写归一后去重，保留一个 ID、合并来源；同一来源不会重复追加。不会自动认定意思相近的两句话相同，AI 应先查询再决定是否纠错。

## 纠错与失效

```powershell
python scripts/gsp.py --project E:\MyProject learn --supersedes <旧ID> --text "新的结论及条件" --reason "为何修正" --source "新的验证证据"
python scripts/gsp.py --project E:\MyProject learn --invalidate <ID> --reason "不再适用的原因" --source "发现问题的来源"
```

纠错创建新 ID，旧项变成 superseded 并指向新项；失效将旧项标成 invalid。旧原文、来源和事件均保留。不能用重复保存旧内容复活无效项；应带证据形成新的适用结论。操作只接受有效目标并要求理由和来源，防止误改历史。

## 文件如何流转

唯一记录为目标项目 `docs/gsp/learnings.jsonl`，兼容旧版每行一条经验的格式；新版在同一日志追加 add/source/invalidate 事件，原始记录不会覆盖。CLI 根据事件生成当前状态、来源列表及替代关系，`--history` 同时返回相关事件。没有第二份可失效索引，也不需要人工迁移。

AI 日常通过 CLI 读有效结论；人需要追溯时看 `--history` 输出或 JSONL 原始事件。不要直接修改已有事件。损坏行、未知事件或非法关系会拒绝继续写入，先恢复备份和调查；不静默跳过。文件发布使用原子替换，CLI 使用项目写锁。不会自动跨项目合并、同步 gbrain，或保存完整敏感会话。
